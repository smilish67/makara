# Makara로 컨셉을 정하고 첫 시안을 검토하는 방법

Makara의 목표는 새 작업에서 설계 대화를 짧고 깊게 만들고, 첫 시안에 사용자가 의도한 경험이 드러나게 하는 것이다. 공모전과 개인 프로젝트 모두에 적용한다. 아래는 에이전트가 따르는 작업 규약이다. 실행 도구의 모델 선택과 구독 인증은 각 도구에서 관리한다.

## 1. 무엇을 만들지 정할 때

설계는 현재 세션의 에이전트가 맡는다. 컨셉 후보가 갈리거나 사용자의 예시를 그대로 구현하는 것과 일반화하는 것 사이에 차이가 크면, 어떤 답이 설계를 바꾸는지 먼저 생각한다. 예를 들어 “1+1을 계산한다”는 예시를 들었다면 “다른 숫자와 연산도 같은 화면에서 입력해야 하나요?”라고 물을 수 있다. 정해진 사양을 구현하거나 오류를 고칠 때는 필요한 프로젝트 정보만 쓴다.

과거 선택이 도움이 될 때 Makara에서 접근이 허용된 관련 사례를 조회한다. 당시의 목적과 제약, 사용자가 직접 밝힌 이유, 출처를 함께 제시한다. 사용자가 고를 법한 방향을 먼저 보여주고 더 넓게 탐색할 후보를 덧붙인다. 이미 고른 뒤라도 이유를 알면 다음 설계가 달라지는 지점에서 한 가지를 묻는다. 사용자가 이유까지 설명했다면 그 답으로 진행한다.

## 2. 작은 첫 시안으로 방향을 판단할 때

시안을 보여줄 때 **표현하려는 경험과 그것을 확인할 장면을 먼저 설명한다.** 설계자는 사용자가 핵심 동작을 직접 해볼 수 있는 최소 범위를 잡는다. 여러 방향이 가능하면 차이가 생기는 장면이나 컴포넌트부터 비교한다. 사용자는 어느 방향을 확장할지, 멈출지, 어떤 부분을 조합할지 판단한다.

가령 추리게임이라면 기사 한 장과 증언 하나로 시안을 만들 수 있다. 설계자는 “나중에 들은 증언 때문에 처음 읽은 기사를 다시 보고 싶어지는 경험”을 의도로 제시한다. 플레이어가 그 시점에 접한 정보와 가능한 행동을 점검한다. 사용자는 의도한 재미가 구현됐는지 판단한다. 처음 접한 플레이어가 실제로 무엇을 알아차렸는지는 플레이 관찰로 확인한다. 사용자가 “뭘 해야 할지 모르겠다”고 하면 막힌 원인을 찾고 대안을 만드는 일은 설계자의 몫이다.

## 3. 구현을 위임하거나 모델을 바꿀 때

| 역할 | 인계하는 내용 |
|---|---|
| 설계 담당 | 선택한 컨셉과 이유, 시안의 범위, 사용자가 직접 해볼 행동, 확인할 기준 |
| 구현 담당 | 실행 가능한 시안, 확인한 결과, 의도와 다르게 구현된 부분, 남은 설계 질문 |
| 기억 처리 | 허용된 대화에서 선택·이유·조건을 추론한다. 프로젝트의 확정 결정과 결과는 요청 시 Markdown 위키에 정리한다. |

설계와 구현에는 그때 이용 가능한 실행 도구·모델·인증 프로필을 선택할 수 있다. 구현자는 이번 작업에 필요한 정보만 전달받고, 컨셉 자체를 바꿀 결정은 설계자와 사용자에게 돌려준다. 기억 생성 모델은 작업 모델과 독립적으로 운영한다. 제공자가 바뀌면 해당 제공자에게 공유가 허용된 자료만 사용한다. 구독 잔여량에 따른 자동 전환은 이 규약의 기능 범위 밖이다.

## 4. 다음 작업이 좋아졌는지 확인할 때

작업 정리를 요청받으면 아래 질문에 답할 수 있는 근거를 연결한다.

1. 어떤 과거 경험을 가져왔고 어떤 조건이 이번 작업과 비슷했는가?
2. 그 경험 때문에 달라진 질문이나 설계는 무엇이며 사용자는 뭐라고 답했는가?
3. 첫 시안의 어느 부분에서 그 답을 직접 확인할 수 있는가?
4. 사용자는 무엇을 유지·수정·조합·중단했으며 어떤 이유를 밝혔는가?
5. 다음 프로젝트에 적용할 수 있는 조건은 무엇이고, 아직 확인할 것은 무엇인가?

사용자의 발언, 에이전트의 해석, 실제 관찰을 구별한다. 범위를 넓힐 근거는 사용자가 직접 밝힌 일반 원칙이나 비슷한 조건에서 반복된 선택이다. 사용자의 침묵에서 선택 이유를 추론하지 않는다. 방향이 빗나갔다면 사례 선택과 질문을 검토하고, 방향에 동의했는데 시안이 약했다면 구현 지시와 결과물을 대조한다. 다음 첫 시안에서 같은 지적을 되풀이할 필요가 줄었는지가 개선의 증거가 된다.

허용된 대화의 자동 수집과 위키 편집은 각각의 기존 정책을 따른다. 위키와 개인 현황 문서는 사용자가 정리를 요청했을 때 갱신한다.
